## 7. SOVEREIGNTY / SELF-SUSTAINING CHARACTER — LOCKED
Pantavion should progressively reduce avoidable dependency on third-party machines, platforms, agents and providers by building Pantavion-owned or self-hostable capabilities where technically, legally, economically and operationally sensible.

Every important capability must expose one current sovereignty state:

- `PANTAVION_OWNED`
- `SELF_HOSTABLE`
- `THIRD_PARTY_WITH_FALLBACK`
- `EXTERNAL_REQUIRED`
- `UNKNOWN`

Rules:

1. External dependency is never hidden.
2. Pantavion must never claim independence while an external dependency is still required.
3. Prefer Pantavion-owned execution when it can meet security, reliability, cost, legal and quality requirements.
4. Preserve working providers/fallbacks while a replacement is being built.
5. Replacement path: research -> adapter/native design -> sandbox -> tests -> canary -> rollback-ready migration -> production verification.
6. Old provider/runtime is retired only after the replacement is `VERIFIED_LIVE` and rollback evidence exists.
7. Security, privacy, jurisdiction, age protections and user isolation cannot be weakened merely to gain independence.
8. Critical or irreversible replacement remains founder-gated.
9. The ecosystem must continuously measure provider lock-in, outage impact, privacy exposure, cost, switching cost and replacement feasibility.
10. The long-term objective is maximum practical sovereignty, not fake "zero external dependency" marketing.

Canonical runtime contract:
`core/kernel/pantavion-sovereignty-loop.ts`

## 9. RECOVERY / PRESERVATION DOCTRINE — LOCKED
Pantavion history is not disposable.

Historical projects, code, files, conversations, artifacts and recovery records are donor/evidence sources for the one canonical `pantavion-planet`.

Preservation corridor:

`SOURCE -> EXACT PRESERVATION -> HASH/PROVENANCE -> CLASSIFICATION -> CANONICAL COMPARISON -> TARGET PLACEMENT -> EXECUTION ADAPTER/WORK ORDER -> TEST -> DEPLOY -> VERIFIED_LIVE`

Never rewrite or recreate an original when the original can be preserved.
Never delete a donor/source because a similar destination exists.
Delete/archive only after exact preservation, uniqueness review, canonical destination verification and owner approval.

Recovered/classified is not the same as implemented/live.

## 10. UNIVERSAL ARTIFACT CHARACTER
Pantavion should accept and preserve diverse historical and modern digital formats, including documents, text, images, photography, audio/music, video, CAD/DWG/DXF, GIS/maps, structured data, databases, archives, code, 3D/BIM and legacy/unknown formats.

Unknown or unsupported formats are preserved and marked for an adapter; they are not silently discarded.
Executable/high-risk formats are isolated/sandboxed and never directly executed merely because they were uploaded.
Original artifacts remain immutable; edits/conversions/renders create provenance-linked derivatives/versions.

`ACCEPT` does not automatically mean `VIEW`, `EDIT`, `EXECUTE` or `VERIFIED`.
Capability truth must remain explicit.
