# Pantavion Permanent System Invariants — 2026-09-22

## Purpose

Pantavion must continuously become safer, faster, more intelligent, more capable and more current without sacrificing truth, memory, security, reversibility, legal boundaries, user agency or provenance.

No subsystem may claim perfection or infallibility. The required engineering target is stronger:

- prevent avoidable failure;
- fail closed when authority or truth is uncertain;
- detect and isolate faults quickly;
- preserve evidence;
- recover deterministically;
- roll back safely;
- never promote an unproven state to success;
- learn from verified outcomes.

## Permanent constitutional invariants

### 1. Truth before status
No capability is complete because code, UI, a deployment, an AI statement or a provider status says so.

Canonical lifecycle:
`IDEA -> CODED -> TESTED -> MERGED -> DEPLOYED -> VERIFIED_LIVE -> OWNER_OK_FOR_USERS`

Recovery lifecycle:
`SOURCE -> EXACT PRESERVATION -> HASH/PROVENANCE -> CLASSIFICATION -> CANONICAL COMPARISON -> WORK ORDER -> TEST -> DEPLOY -> VERIFIED_LIVE`

Missing evidence is a blocker, not success.

### 2. No-orphan founder vision
Every founder directive, idea, design decision, recovered conversation, artifact, branch, code path, historical project and unresolved requirement must retain one explicit outcome:
`CANONICALIZED | SUPERSEDED_WITH_REASON | ARCHIVED_WITH_PROVENANCE | BLOCKED_WITH_REASON | REVIEW_REQUIRED`.

Nothing disappears merely because a thread, branch, provider, deployment or implementation changes.

### 3. Memory is a constitutional service
Pantavion memory is tiered:
- hot current context;
- warm indexed summaries and decisions;
- cold private immutable archive.

Memory must preserve chronology, source, confidence, decision state, obligations and supersession links. Raw sensitive material remains separated from lightweight runtime memory.

### 4. Multi-kernel, one truth
Pantavion may use many kernels, agents, models, providers and workers in parallel, but they share:
- one canonical truth plane;
- one identity/authority model;
- one provenance model;
- one implementation lifecycle;
- one audit/observability contract.

Parallelism may increase throughput; it may not create competing truths.

### 5. Maximum useful intelligence under bounded authority
For each task, Pantavion should select the strongest available intelligence that meets the required quality, latency, cost, privacy, jurisdiction, safety and reliability envelope.

Routing may use:
- fast/instant intelligence;
- deep reasoning;
- specialist models;
- deterministic code;
- search/retrieval;
- workflow/agent execution;
- restricted/high-risk modes.

Model capability never grants authority. Identity, consent, policy, risk, budget and reversibility govern action.

### 6. Speed without silent corruption
Low latency is a product requirement, but speed may not bypass:
- idempotency;
- fencing/leases;
- deterministic identity;
- conflict detection;
- validation;
- provenance;
- audit;
- rollback.

Fast wrong writes are worse than slower correct writes.

### 7. Zero-trust and least privilege
All privileged paths are deny-by-default. Secrets never enter client bundles, chat transcripts, public logs or repository evidence.

Critical controls:
- least privilege;
- short-lived credentials where practical;
- service-role isolation;
- RLS / private schemas / explicit grants;
- session and authority checks;
- scoped agent capabilities;
- secret rotation;
- immutable security audit evidence.

### 8. Immutable originals, versioned derivatives
Recovered artifacts, source engineering files, evidence, raw user-provided originals and canonical master records remain immutable whenever possible.

Byte-changing work creates derivatives/versions with:
- source hash;
- transformation method;
- tool/model identity;
- timestamp;
- approval state;
- rollback path.

### 9. Reversibility before production
High-impact production changes require:
- bounded blast radius;
- checkpoint/backup where applicable;
- migration evidence;
- rollback path;
- observability;
- owner/security gate where required.

Irreversible change without required evidence is prohibited.

### 10. Modern technology intake is continuous, not reckless
Pantavion continuously observes AI, models, agent systems, databases, protocols, infrastructure, security, cryptography, search, robotics, devices, geospatial systems, media, scientific advances and relevant standards.

Every candidate enters:
`DISCOVER -> RESEARCH -> LICENSE/LEGAL CHECK -> SECURITY CHECK -> BENCHMARK -> SANDBOX -> COMPARE -> CODE CANDIDATE -> TEST -> CANARY -> PROMOTE OR REJECT`.

A newer technology is not automatically better. Adoption requires measured benefit.

### 11. Provider neutrality and sovereignty
External providers remain replaceable where practical. Every critical capability must expose its current sovereignty state:
`PANTAVION_OWNED | SELF_HOSTABLE | THIRD_PARTY_WITH_FALLBACK | EXTERNAL_REQUIRED | UNKNOWN`.

Provider retirement requires verified replacement and rollback evidence.

### 12. Evidence-bound self-improvement
Kernels and agents may research, propose, simulate, benchmark and prepare improvements autonomously. They may not silently rewrite canonical truth or self-promote to production.

Self-improvement mode remains proposal-governed until the required release gates are satisfied.

### 13. Human-first authority
The human remains the decision authority for founder-gated, sensitive, irreversible or high-impact actions. AI supports judgment; it does not invent permission.

### 14. Security, privacy, minors, law and jurisdiction outrank feature speed
No optimization, growth target, provider migration, AI capability or automation may weaken mandatory safety, privacy, age, legal or jurisdiction controls.

### 15. Observability is part of correctness
A capability without health, evidence, provenance and failure visibility is not operationally complete.

Critical systems must expose:
- status;
- exact blocker;
- owner;
- source revision;
- evidence;
- last successful verification;
- rollback state;
- current lifecycle state.

### 16. No static/fake-live Pantavion
No dead buttons, fake dashboards, mock production numbers, invented success states or placeholder capabilities may be presented as real.

If a capability is unavailable, Pantavion says unavailable and records the blocker.

## Founder continuity rule

The original Pantavion vision from its earliest lineage through current and future directives remains recoverable and attributable. New decisions may evolve earlier ideas, but they do not erase them. Supersession must preserve the previous state and the reason for change.

## Future technology rule

Pantavion must continuously evaluate modern technology, but production adoption is evidence-driven. The goal is not to chase every release. The goal is to maintain the strongest safe and sustainable architecture available for Pantavion's mission.

## Error doctrine

"Zero errors" is not treated as a marketing claim. Pantavion's engineering objective is:
`PREVENT -> DETECT -> CONTAIN -> RECOVER -> VERIFY -> LEARN`.

A detected error must become evidence for a stronger invariant, test, guardrail or recovery path whenever technically appropriate.

## Non-negotiable preservation rule

No historical Pantavion source, idea, record or artifact may be destroyed merely because it appears duplicated. Deduplication preserves provenance edges and only removes duplicate execution/processing work after deterministic proof.
