# Pantavion Planet — Global Capability Gap-to-Implementation Contract

## Purpose
Build original, verified capabilities across every canonical product family. Competitor research is functional benchmarking, not copying proprietary source, branding, private APIs or bypassing access controls.

## Per-capability evidence record
Each feature requires: canonical family and capability ID; founder requirement/provenance; country and locale; comparable products and publicly documented workflows; user problem; competitor limitation; proposed Pantavion improvement; lawful interoperability route; data classification and consent; backend schema and RLS; API and UI integration; tests; deployment proof; owner and status.

## Social Core first vertical
1. People: authenticated profiles, discoverability controls, consented relationships, block/report.
2. Contacts: user-confirmed CSV/vCard/device import; provenance, revoke/delete and no external scraping.
3. Chat: authenticated 1:1 messaging, persisted receipts, group membership policy, translation with original-language preservation.
4. Social: posts, reactions, comments, media permissions, moderation.
5. Communities: creation, membership, roles, reporting and non-recursive RLS.
6. Connections/dating: opt-in age-gated isolated visibility; never expose sensitive identity, orientation or location by default.
7. Global accessibility: localization, assistive UX, low-bandwidth and transparent AI translation fallbacks.

## Release gates
RESEARCHED: cited competitor functionality and gaps.
SPECIFIED: acceptance criteria, risk, data flows and consent.
IMPLEMENTED: code + migrations + connected UI on reviewed branch.
TESTED: CI, RLS, negative security cases, two-account end-to-end journeys.
DEPLOYED: reviewed deployment with migration verification and rollback.
VERIFIED_LIVE: observed production journeys with timestamped evidence.

A route, mock, migration file, passing unit test, or draft PR alone never means VERIFIED_LIVE. Do not merge donor branches wholesale; selectively port unique value and record provenance. Every known gap must be assigned an owner and tracked until resolved or explicitly blocked.
